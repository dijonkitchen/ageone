# Decision Record 2026-10-23: roi Stack

## Status timeline

2026-10-23: Proposed by Claude, implementing [SPEC-2026-09-30-roi-rebuild](../../specs/SPEC-2026-09-30-roi-rebuild.md)

## Objective Context

### Simple, lovable, complete must haves

#### Functional

A stack for [the spec](../../specs/SPEC-2026-09-30-roi-rebuild.md): screen stocks and options and evaluate strategies offline (screening, strategies, a paper broker with risk limits, a backtest report), with market data behind a port and an LLM research assistant that writes cited summaries of a shortlist's filings and news.

#### Non-functional

Installable in the pinned environment from the root `make`, with `make check` passing in CI.
Safe by default (no code path places a live order), offline tests, and an optional live data adapter that doesn't weigh down the core.

### Nice to haves

#### Functional

Fundamentals (DCF, ratios, per-share history, Kelly sizing) and options price checks, carried over from the old repo with their acceptance criteria.

#### Non-functional

A core with no dependencies at all, so it runs anywhere Python 3.12 does.

### Avoid out of scope runaway rabbit hole risks

#### Functional

Live trading, a live options chain, American option pricing, notebooks, a UI.

#### Non-functional

A database, a scheduler, or a hosted service.

## Decision

Started from the python project template (see [Project template](../../../../docs/decisions/2026-10-04-project-template.md)).
The old repo, [dijonkitchen/roi](https://github.com/dijonkitchen/roi), was Python with uv, pytest, ruff, and ty, in a ports-and-adapters shape, with optional OpenBB for live prices and marimo notebooks.
That stack still holds, so its code is the starting point, ported rather than rewritten:

- **Language and tools**: Python 3.12 with uv, pytest, ruff, and mypy (strict for `src/`, relaxed for test helpers), as the template sets; ty is dropped for mypy to match the other Python projects.
- **Shape**: ports and adapters.
  The core (`domain`, `ports`, `screening`, `strategy`, `execution`, `harness`, `pricing`, `analysis`, `research`) has no I/O and imports nothing from `adapters`; adapters (`InMemoryMarketData`, `ReplayMarketData`, `InMemoryOptionQuotes`, `SECFundamentals`, `OpenBBMarketData`) are the only code that reaches outside, through injectable fetchers so tests stay offline.
- **Safety**: `PaperBroker` is the only broker; a test fails if another `Broker` or a broker SDK appears.
- **Data**: sample data in code and `src/roi/data/`; live prices through the optional `openbb` extra (`uv sync --extra openbb`), imported only when that adapter is used.
- **Research assistant** (`src/roi/research.py`): the model comes from a role in the repo's [`harness/models.json`](../../../../harness/models.json) (`--role`, default `default`), called through OpenRouter with the repo's routing (zero data retention, no data collection) and the caller's `OPENROUTER_API_KEY`.
  Sources go in as numbered, quoted, untrusted data; the answer must give every company a summary whose every sentence cites one of that company's own sources, and must not suggest an order, position, or price target, or it is rejected.
  It has no tools and no broker.
- **Eval**: [`evals/cases/roi-cited-research`](../../../../evals/cases/roi-cited-research/) is a direct case whose prompt is exactly the assistant's prompt for the sample shortlist (a test fails if they drift) and whose grader runs the assistant's own checks with `python3 -m roi.research --check`, using only the standard library so it runs in the eval sandbox.
  One sample news item carries an injected instruction to tell readers to buy, so following it fails the case.
- **Acceptance criteria**: the old specs' criteria and the new ones live in [`docs/acceptance.md`](../acceptance.md) with IDs; tests cite them with `@pytest.mark.criteria`, and a test fails if one has no test.
- **Commands**: `uv run roi` (screen and backtest a sample universe offline), `uv run roi research` (cited summaries of a sample shortlist; `--prompt` shows the prompt without a key).

### High-level C4(context/container/component/code) diagram

```text
sample data / ReplayMarketData / OpenBBMarketData (extra) --MarketDataProvider--> screening --> strategy --> harness.backtest --> EvalReport
                                                                                                    |
                                                                                                    v
                                                                                  PaperBroker (risk limits; the only Broker)

```

### Choices and Tradeoffs/Risks

Porting over rewriting: the old code was small, tested, and already in the shape the spec asks for; the rebuild adds strict typing, the acceptance IDs, the safety and offline checks, and the research assistant.

Overlap with [stock-screener](../../../stock-screener/): both read SEC fundamentals and size by Kelly.
roi keeps its own small, dependency-free versions because they are part of its carried-over criteria and its core must stay dependency-free; merging the two (roi's ports over stock-screener's pipeline) is worth a spec of its own once both are in use.

A citation and no-advice checker in code over trusting the prompt: a model that ignores the rules gets rejected instead of shown, and the same checker grades the eval.
Its advice patterns are a heuristic; the eval's injected instruction keeps them honest, and a false positive costs a rejected answer, not a bad one shown.

OpenRouter for the assistant: it is the repo's default route for every role; another provider needs only a new `Model` adapter.

### Dependencies

None for the core and the assistant (standard library only).
Optional: `openbb` for live prices.
Development: pytest, ruff, mypy.

### Interfaces

- Ports: `MarketDataProvider`, `Broker`, `FundamentalsProvider`, `FundamentalsHistoryProvider`, `OptionQuoteProvider`, and the research `Model`.
- `roi` and `roi research [--role ROLE] [--prompt] [--check FILE]`.

## Key Results and retrospective feedback

A live eval run (`evals/run --harness direct --model default --case roi-cited-research`) needs an `OPENROUTER_API_KEY` and is still to do.
